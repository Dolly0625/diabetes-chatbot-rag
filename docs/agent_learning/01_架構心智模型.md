# 01｜架構心智模型

## Agent 的任務

正常路徑是：

```text
User → A → Query Expansion → RAG → B → C → D → Answer
```

Agent 只在 B 回傳 `INSUFFICIENT` 且呼叫端有提供 `agent_planner` 時介入：

```text
                           ┌──────── PASS ───────→ C → D
User → A → Expansion → RAG → B
                           └── INSUFFICIENT ────→ Agent Planner
                                                    ├─ ASK_USER → 結束本次 request
                                                    ├─ REWRITE_QUERY → Expansion → RAG → B
                                                    └─ FALLBACK → 安全結束
```

因此它不是主要回答者。它的工作是回答一個更窄的問題：

> B 說目前證據不足，下一個允許的恢復動作是什麼？

## 五種權責

| 元件 | 權責 | 不能做的事 |
| --- | --- | --- |
| A Input Router | 決定 request 是否可進 RAG | 不把政策封鎖交給 Agent 推翻 |
| RAG | 找候選 evidenceㄌ | 不批准 evidence，也不選 Agent action |
| B Context Gate | 判斷 evidence 是否足夠／安全 | 不直接控制 Agent 路由 |
| Agent Planner | 從三個 action 中選一個 | 不回答、不批准 evidence、不決定 graph node |
| LangGraph | 執行 action、計數、限制與路由 | 不把控制權交給 LLM |

最重要的設計原則是 **decision 與 execution 分離**：

- LLM 提出一個已限制格式的 decision。
- Pydantic 驗證 decision。
- Graph 再檢查次數限制。
- Graph 將 decision 映射到固定節點。

## 為什麼需要 Agent

沒有 Planner 時，`run_workflow()` 保留 deterministic baseline：B 一旦 `INSUFFICIENT` 就 fallback。提供 Planner 後，系統多出有限恢復能力：

- 缺少只能由使用者提供的必要事實：詢問使用者。
- 使用者事實完整，但字詞不利於檢索：改寫 query。
- 已嘗試合理恢復或 corpus 根本沒有證據：fallback。

## 這不是什麼

本專案目前不是：

- 自主選工具的 ReAct Agent。
- 可以動態建立任務清單的 planner/executor。
- 有長期記憶的對話 Agent。
- 可以自行決定重試次數的 Agent。
- 可以直接產生醫療答案的 Agent。

`ASK_USER` 也不代表 graph 暫停後保留同一個執行實例。demo 的做法是先回傳 `NEEDS_CLARIFICATION`，收到補充資料後建立新 request，重新從 A 進入。

## 三條主要路徑

### ASK_USER

```text
B insufficient
→ Planner: ASK_USER
→ deterministic question builder
→ NEEDS_CLARIFICATION
→ 使用者補充
→ 新 request 從 A 重新進入
```

### REWRITE_QUERY

```text
B insufficient
→ Planner: REWRITE_QUERY
→ Query Rewriter 產生結構化 rewritten_query
→ 程式碼驗證沒有明顯新增／刪除醫療事實
→ Query Expansion → RAG → B
```

### FALLBACK

```text
B insufficient
→ Planner: FALLBACK
或 graph 將超限 action 改成 FALLBACK
或 Planner／Rewriter 發生錯誤
→ 固定安全訊息
```

## 讀完自我檢查

- B 可以直接要求 Agent 執行 `ASK_USER` 嗎？不行；B 只提供中性的 missing-information observation。
- Planner 可以輸出 `next_node="RAG"` 嗎？不行；schema 禁止額外欄位。
- Planner 可以直接回答醫療問題嗎？不行；輸出 schema 沒有 answer 欄位。
- `REWRITE_QUERY` 後可以跳過 B 嗎？不行；固定重新經過 Expansion、RAG、B。
